AUDIO-DERIVED WORKFLOW (new, recommended)
--------------------------------------
1. In .env: DEMO_MODE=true, AUDIO_ONLY_MODE=true, ASR_PROVIDER=sarvam,
   SARVAM_API_KEY=private API key, SARVAM_MODE=codemix,
   SARVAM_LANGUAGE_CODE=unknown, ALLOW_REMOTE_SYNTHETIC_INPUT=true
   (ONLY for explicitly approved de-identified or synthetic evaluation audio).
2. Set LLM_PROVIDER=bedrock and configure AWS credentials for AI extraction,
   or choose LLM_PROVIDER=demo only for limited rule-based *real-transcript*
   structural parsing; that mode does not call an LLM.
3. Run python scripts/run_real_audio.py (no sample report seeding).
4. Register/select a corresponding VERIFIED test patient (this is still a
   restricted local demonstration with demo authentication), upload actual
   .ogg/.wav/.mp3 audio, and generate draft. Do not type a transcript.
5. Review the raw ASR output, source hash and structured fields; correct
   suspect dates, clinical negations and names against recording.
6. For independent direct Sarvam check, run:
   python scripts/transcribe_real_audio.py --audio C:\\path\\sample.ogg --output C:\\path\\private-result --confirm-approved-upload
   The command makes a real paid API call and cannot run without credentials.
7. Compare transcript.txt to a HUMAN-VERIFIED VERBATIM reference with:
   python scripts/evaluate_transcription.py --reference ref.txt --candidate transcript.txt --critical-phrase "no atypical cells"
   A formatted pathology report is not a verbatim WER reference.
8. For full local verification install requirements-dev.txt and run:
   python scripts/validate_complete.py
This app is NOT clinically validated; do not upload identifiable patient audio
without vendor, data protection, security and organizational authorization.
