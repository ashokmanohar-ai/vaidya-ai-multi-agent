# API and security notes

## Implemented endpoints

| Endpoint | Method | Access | Description |
|---|---|---|---|
| `/` | GET | Public | Demo login redirect or foundation landing |
| `/health/live` | GET | Public | Process health |
| `/health/ready` | GET | Public | Explicitly reports `clinical_ready=false` |
| `/api/v1/status` | GET | Public | Availability and feature claims |
| `/login` | GET/POST | Demo only | Password login with CSRF protection |
| `/logout` | POST | Authenticated | End demo session |
| `/dashboard` | GET | Doctor | Reports for owning doctor |
| `/reports/new` | GET | Doctor | Report form |
| `/reports/create` | POST | Doctor | Synthetic dictation, image intake and DOCX output |
| `/reports/<id>` | GET | Owner doctor | View draft/final |
| `/reports/<id>/download` | GET | Owner doctor | Draft DOCX |
| `/reports/<id>/approve` | POST | Owner doctor | Final text and mandatory attestation |
| `/reports/<id>/final-download` | GET | Owner doctor | Final DOCX |
| `/api/v1/jobs` | GET | Doctor | Own jobs |
| `/api/v1/jobs/<id>` | GET | Owner doctor | Job status, durable checkpoint and stage events |
| `/api/v1/jobs/<id>/graph` | GET | Owner doctor | Checkpoint ID, pending nodes, node trace |
| `/reports/<id>/resume` | POST | Owner doctor | Retry a saved doctor-reviewed graph checkpoint |
| `/admin` | GET | Admin | Learning and governance view |
| `/admin/learnings/<id>/decision` | POST | Admin | Approve/reject/defer learning |

## Security controls present in this synthetic demo

- Passwords hashed with PBKDF2-HMAC-SHA256 and random salt; role-scoped server-side view access.
- Session cookie HttpOnly + SameSite, CSRF tokens on mutating HTML forms.
- Document download ownership checks, synthetic hospital scoping, sanitized filenames generated by server.
- Uploaded image format and size checks via Pillow, private local storage folder and CSP.
- All clinical suggestions require doctor review; skill activation requires an admin role, 5 supporting distinct jobs, and audit record.
- Demo mode disabled by default; no anonymous report generation. Bedrock API calls require server-side environment opt-in.

## Important omissions before live clinical use

- Account lockout/rate limiting, multi-factor authentication, password recovery and external identity provider.
- Managed PostgreSQL tenant isolation, row-level policies, secure audit retention, backups.
- Encryption at rest with managed keys, malware screening, retention/deletion workflows.
- Approval of vendor/region data processing, explicit patient consent basis/legal analysis, clinical evaluation.
- Cloud-distributed job handling, PostgreSQL-backed durable checkpoints, and multi-worker idempotency. (Local SQLite LangGraph checkpoints are implemented for the demo.)
- Clinical report provenance at a field level, source-grounding and medically reviewed output benchmarks.

Do not treat demo security measures as a production assessment.
